# 旧地图升级教程：迁移到 MapPath V2 路径系统

> 适用于使用旧版路径索引（`mapIndex`）的地图。升级后，地图将使用新版 **MapPath V2 有向路径**，支持岔路选择、单向通行、动态路线开关等能力。

## 一、升级前准备

升级前请先做好以下准备：

1. **备份原地图**  
   建议先复制一份旧地图文件，或通过编辑器的版本记录保存一个可回退版本。

2. **更新地图编辑器**  
   请确认已使用支持 **MapPath V2** 的地图编辑器版本。

3. **了解升级影响**
   - 旧版路径索引会自动转换为新版地图路径。
   - 地图中的原有地块、建筑、事件等内容不会因此被删除。
   - 升级后请重新检查路径方向、岔路口和传送相关事件。

> **操作提示：** 升级前先保存一份可回退的原始地图。完成迁移后，可从地图起点开始逐段核对路径箭头，确认整体路线与原地图设计一致。`r`n`r`n
## 二、打开旧地图并确认自动迁移

1. 在地图编辑器中打开旧地图。
2. 如果该地图尚未使用新版路径配置，编辑器会弹出提示：
   - 已根据旧版路径索引自动生成路径；
   - 提示生成的路径数量；
   - 提醒你可以在“地图路径”中查看和调整。
3. 点击 **“知道了”**，进入地图编辑界面。

> **操作提示：** 弹窗中的路径数量仅表示编辑器根据旧数据自动生成的连接数量；它不代表路线已完成验收，仍需在后续步骤中检查方向和分叉。`r`n`r`n
### 自动迁移后发生了什么？

编辑器会根据旧地图的路径索引，自动生成新版的 **有向路径**。这一步只是将旧数据转换成可编辑的新路径数据；仍建议你手动检查路线，特别是：

- 起点和终点是否正确；
- 是否存在不应连通的相邻格子；
- 岔路口的可选方向是否符合原设计；
- 单向路线、回环路线和死路的方向是否正确。

## 三、生成并检查新版地图路径

### 1. 打开“地图路径”面板

在编辑器顶部工具栏中点击 **“地图路径”**。

> **操作提示：** “地图路径”用于集中生成、预览和保存路线；建议在调整地图格子布局后，再进入此面板重新生成路径。`r`n`r`n
打开后，会看到“路线预览”和“生成设置”区域。

> **操作提示：** 该面板中的“生成路线预览”不会修改地图数据；只有点击“保存路线”后，新的路径配置才会正式写入当前地图。`r`n`r`n
### 2. 选择需要参与路径生成的地图格

在地图中选中需要作为行走路线的地图项。通常应选择道路、格子或其他实际可供玩家停留、移动的路径节点。

然后在“地图路径”面板中确认：

- **路径节点类型**：选择本地图实际使用的路径节点类型；
- **地图起点**：选择玩家开局所在的起始格。  
  如果暂不选择，编辑器会使用第一个路径节点作为起点。

> **操作提示：** 不要把装饰物、不可停留区域或仅作视觉表现的地图项纳入路径节点；错误选择会导致生成额外连接。`r`n`r`n
### 3. 生成路线预览

点击 **“生成路线预览”**。

编辑器会依据相邻关系生成路线：上下左右直接相邻的路径节点会形成单向连接。此时生成的只是**预览**，还没有正式写入地图。

预览中会以箭头显示路径方向。请重点检查：

- 主路线是否连续；
- 起点是否位于正确位置；
- 岔路口是否能通往预期方向；
- 不相邻的格子之间是否没有错误连线；
- 死路是否按预期回退或终止；
- 回环路线是否完整闭合。

> **检查重点：** 若两个路径节点在上下左右方向直接相邻，编辑器会尝试生成连接。对于视觉上相邻、玩法上不应连通的格子，请在保存前删除错误路径或调整布局。`r`n`r`n
## 四、调整路线方向

MapPath V2 使用“从起点到终点”的有向路径。箭头方向决定玩家能沿哪一侧移动，因此路线方向需要仔细确认。

在“路线方向”区域中，编辑器会按端点或分叉点将路径划分为多条路线。每条路线都可以单独点击 **“反转方向”**。

### 什么时候需要反转方向？

以下情况通常需要使用“反转方向”：

- 整段主路线箭头全部反了；
- 某个岔路分支应由主路进入，但现在变成从分支返回主路；
- 单向道路的方向与地图设计不一致；
- 终点、传送点或特殊事件要求玩家从特定方向进入。

> **操作提示：** “反转方向”会同时调整整段路线，而不是只改变某一小段连接。遇到主路线整体反向时，优先使用该操作。`r`n`r`n
### 调整建议

1. 先从地图起点开始，沿箭头逐段检查主路线。
2. 遇到岔路口时，确认每条分支的箭头都指向合理。
3. 若一整段路线反向，不要逐条删除重建，直接使用 **“反转方向”**。
4. 调整后再次观察地图上的箭头变化，确认无误后再保存。

## 五、保存升级后的路线

确认路线预览和方向都正确后，点击 **“保存路线”**。

保存后，预览中的路径会正式写入地图，替换当前地图的路径配置。此时旧地图已完成路径数据升级。

> **保存前确认：** 请至少检查一次起点、主路线、每个岔路口和死路。保存路线会覆盖当前路径配置，如需回退可使用升级前备份或版本记录。`r`n`r`n
然后使用顶部菜单的 **“保存”** 或 **“保存为项目”** 保存地图文件。

> **操作提示：** 路径保存和地图文件保存是两个步骤：先在“地图路径”中保存路线，再通过顶部菜单保存整个地图项目。`r`n`r`n
## 六、逐条检查与微调路径

保存路线后，切换到选择模式，在地图上点击一条路径，即可打开 **“路径详情”**。

在路径详情中可以查看和修改：

- **路径 ID**
- **起点**
- **终点**
- **名称**
- **说明**
- **初始启用状态**

还可以进行以下操作：

- **保存**：保存当前路径的属性修改；
- **反转起终点**：仅反转这一条路径的方向；
- **删除**：删除错误路径；
- **复制 ID**：复制路径、起点或终点 ID，便于编写事件和排查问题。

> **操作提示：** 批量调整优先使用“地图路径”面板；仅个别连接有问题时，再通过“路径详情”修改、反转或删除单条路径。`r`n`r`n
### 常见微调场景

| 场景 | 处理方式 |
|---|---|
| 单条箭头方向错误 | 选中路径，点击“反转起终点” |
| 自动生成了不该存在的连接 | 选中错误路径并删除 |
| 地图新增了道路格 | 重新打开“地图路径”，选择相关节点后重新生成并保存 |
| 路径需要给地图创作者备注 | 在“名称”或“说明”中补充用途 |
| 路径初始不应开放 | 关闭“初始启用”，再通过事件动态开启 |

## 七、迁移旧版传送事件

旧地图中如果使用了旧版传送接口：

```ts
player.tp(positionIndex)
```

建议改为新版按地图项 ID 传送：

```ts
player.tpToMapItem(mapItemId)
```

例如：

```ts
async (cmd, ctx) => {
  const player = ctx.player;
  await player.tpToMapItem("mi-xxxxxx");
}
```

新版写法不再依赖旧路径位置序号，而是直接指定目标地图项 ID。这样即使后续调整了路线顺序，也能更稳定地传送到正确位置。

### 如何获取地图项 ID？

可以在编辑器中选中目标地图项后查看其 ID；如需统一整理地图项 ID，也可以在顶部菜单的工具项中使用：

**“重命名全部 MapItem ID（标准格式）”**

> 注意：该操作会批量重命名全部地图项，并自动同步地图内部引用。建议先保存地图或确认已有版本记录后再执行。

> **操作提示：** 批量重命名会修改所有地图项 ID，并同步更新地图内部引用。外部文档、脚本或 effectCode 中手写的旧 ID 不会自动修改，请在操作后逐一检查。`r`n`r`n
## 八、MapPath V2 新 API 参考

本节补充旧地图升级后可使用的路径相关 API。它们分为两类：

- **游戏进程 API**：用于地图事件、游戏阶段或自定义库中的运行时玩法逻辑；
- **地图编辑器 MCP 工具**：用于已连接地图编辑器的 AI 读取、维护或批量生成路径图。

### 1. MapPath 数据字段

每条 MapPath V2 路径都是一条有向连接，包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `string` | 路径唯一 ID；通过编辑器或 MCP 创建时可以自动生成 |
| `fromMapItemId` | `string` | 路径起点地图项 ID |
| `toMapItemId` | `string` | 路径终点地图项 ID |
| `initEnable` | `boolean`（可选） | 地图初始化时是否开放；省略时默认开放 |
| `name` | `string`（可选） | 供编辑器识别和展示的名称，不影响选路逻辑 |
| `description` | `string`（可选） | 供编辑器识别和展示的说明，不影响选路逻辑 |

### 2. 游戏进程 API

以下方法位于 `gameProcess` 实例上。适合在游戏阶段回调、自定义库或能够取得 `gameProcess` 的运行时逻辑中调用。

| API | 说明 |
|---|---|
| `getMapPathById(pathId)` | 根据路径 ID 获取一条路径；路径不存在时返回 `undefined`。 |
| `getPathMapItemIds()` | 获取全部可行走地图项的 ID，即类型被配置到 `pathMapItemTypeIds` 中的地图项。 |
| `getAvailableMapPaths(mapItemId, direction)` | 获取指定地图项在实际移动方向上的当前可走路径。`direction` 可为 `"forward"` 或 `"reverse"`；返回顺序与地图中路径的保存顺序一致。 |
| `isMapPathEnabled(pathId)` | 查询路径在当前游戏会话中是否启用。 |
| `setMapPathEnabled(pathId, enabled, canPass?)` | 设置路径在当前游戏会话中的启用状态；可额外注册动态通行条件。不会修改静态地图文件。 |

#### 示例：按条件开启一条路线

```ts
const path = gameProcess.getMapPathById("mp-bridge");
if (!path) return;

gameProcess.setMapPathEnabled(path.id, true);
```

#### 示例：设置动态通行条件

```ts
const pathId = "mp-toll-road";

gameProcess.setMapPathEnabled(pathId, true, (player, path) => {
  // 玩家拥有至少 200 金钱时才允许通过。
  return (player.money ?? 0) >= 200;
});
```

> **注意：** 动态通行条件只存在于当前游戏会话中，不会写回地图静态数据。路径关闭时会清除其通行条件；再次启用但不传入 `canPass` 时，也会清除先前条件。动态条件仅在沿路径原始方向正向进入时检查，自动选路会跳过不满足条件的路线。

### 3. 地图编辑器 MCP 路径工具

已连接地图编辑器 MCP 服务的 AI 可通过以下工具管理 MapPath V2。进行生成、批量修改或迁移检查前，建议先调用 `get_map_path_graph` 获取当前路径图及旧版兼容状态。

| MCP 工具 | 用途 | 关键参数 |
|---|---|---|
| `get_map_path_graph` | 获取完整路径图、可行走地图项类型、地图起点、旧版 `mapIndex` 和兼容状态。 | 无 |
| `list_map_paths` | 按条件列出路径。 | `mapItemId`、`direction`（`outgoing` / `incoming` / `all`）、`enabled` |
| `get_map_path` | 按 ID 读取一条路径。 | `pathId` |
| `add_map_path` | 新增一条有向路径；同方向的重复连接会被拒绝。 | `fromMapItemId`、`toMapItemId`、`initEnable?`、`name?`、`description?`、`id?` |
| `update_map_path` | 修改路径端点、初始开放状态或展示信息。 | `pathId` 和至少一个待修改字段 |
| `remove_map_path` | 删除一条路径。 | `pathId` |
| `replace_map_paths` | 原子替换整张路径图；适合一次性生成或重建路线。该操作会清空旧版 `mapIndex`。 | `paths` |
| `update_map_path_settings` | 设置可行走地图项类型和地图起点。 | `pathMapItemTypeIds?`、`startMapItemId?` |

#### MCP 使用规则

1. **先读后写**：修改前先调用 `get_map_path_graph`；单条修改前可再调用 `get_map_path` 确认目标。
2. **优先单条操作**：只需修复少数连接时，使用 `add_map_path`、`update_map_path` 或 `remove_map_path`。
3. **批量替换需谨慎**：`replace_map_paths` 会以提交的数组完全覆盖现有路径，并清空旧版 `mapIndex`；执行前应确认输入包含所有需要保留的路线。
4. **地图起点与节点类型**：`update_map_path_settings` 的 `pathMapItemTypeIds` 传空数组时，会恢复按现有路径端点推断；`startMapItemId` 传 `null` 时会清空显式起点，改由旧版 `mapIndex` 或路径节点推断。
## 九、升级后的验证清单

完成保存后，建议实际运行地图并逐项测试：

- [ ] 玩家能从地图起点正常开始移动；
- [ ] 主路线可以完整走通；
- [ ] 岔路口会出现正确的可选方向；
- [ ] 单向路线不能逆向通行；
- [ ] 死路、回环和终点路线符合设计；
- [ ] 地图中的传送、移动类事件能到达正确格子；
- [ ] 动态开启或关闭路线的事件符合预期；
- [ ] 保存并重新打开地图后，路径方向和连接关系没有变化。

## 十、常见问题

### 1. 为什么生成后路线方向不对？

自动生成会根据地图项的相邻位置建立连接，但无法判断你的玩法设计。请在“路线方向”中使用 **“反转方向”** 调整整段路线，或在“路径详情”中反转单条路径。

### 2. 为什么有些格子没有被纳入路线？

请确认该地图项已被选中，并且“路径节点类型”选择正确。只有符合条件、参与生成的地图项才会被加入路线。

### 3. 为什么地图上出现了不该有的连接？

通常是两个路径节点在上下左右方向直接相邻。可删除错误路径，或调整地图布局后重新生成路线。

### 4. 升级后旧地图还能继续使用吗？

可以。旧地图打开时会自动生成新版路径；但只有在你保存地图后，新版路径配置才会被写入地图文件。

### 5. 是否必须立刻修改所有旧版传送代码？

建议在本次升级中一并处理。旧版 `player.tp(positionIndex)` 接口将逐步废弃，新地图应优先使用 `player.tpToMapItem(mapItemId)`。
